# 记忆分区缓存

默认仅发送最近 24 小时聊天原文，时长可在插件设置中修改。覆盖浏览器端在线聊天、线下见面及对应群聊；提示词预览也使用同一条处理链。更早内容生成长期摘要，按近期优先和关键词相关性注入，默认上限 6000 字符。原有 Float 记忆注入继续保留。

## 使用

1. 使用包含配套宿主改动的 Float 构建。旧版本不能只导入插件获得完整功能。
2. 在聊天插件管理页导入同目录的 `memory-partition.js`，或粘贴文件全文并启用。
3. 在插件设置修改“原文保留时长（小时）”。默认 24，可输入小数。

本次不自动安装插件、不部署网站，也不调用你的真实模型。插件总结使用 Float 的默认模型通道，首次整理历史会产生模型调用。每次最多整理 4 批（每批至多约 12000 字符）；若仍有历史，已完成摘要保留，提示再次发送继续整理，聊天请求暂不发送。

## 缓存与失败处理

- 历史原文留在 Float 原存储，不删除或搬移；缓存区是逻辑分区。
- 摘要保存到独立 IndexedDB `float-memory-partition-v1`，按会话和在线/线下模式隔离。它是插件长期摘要库，不写入 Float 记忆银行。在线和线下素材通过宿主已有跨功能时间线参与各自摘要。
- 内容哈希决定摘要复用。修改、删除源记录后，下次只选择当前素材对应的摘要；旧缓存暂保留，不再召回。历史尾批增长时可能重新总结该批。
- 摘要失败、超时、存储失败或时间无效时，本轮不发聊天请求。已有原文保留，避免尚未生成记忆就丢失上下文。跨边界的原生工具结果要求调大时长。
- 原文窗口是发送上限；Float 原有 token 预算仍可能进一步裁剪窗口内内容。摘要有损，关键词召回不保证还原所有细节。首次历史整理仍需要把旧资料发送给总结模型，之后复用缓存。
- 禁用插件恢复宿主原来的上下文行为。独立摘要库不会随卸载自动删除，也尚未接入 Float 备份导出；保留原始聊天备份，清除浏览器数据后可重新生成摘要。
- 仅补充浏览器聊天构建链。服务器推送、微信助手等独立后台链路不在本次范围内。

## 宿主接口

增加 `ctx.meta.contextPartitionVersion = 1` 和 `context.prepare` hook。带时间的 `records` 只用于总结；插件先原地设置 `partition.state = pending`，持久化成功后设置 `ready` 和 cutoff、memory。宿主统一过滤历史原文及跨功能聊天引用，直接注入摘要，失败状态阻止发送。

## 验证

在 Float 目录运行 `node --test plugins/memory-partition.test.mjs`（Node 24）。此测试包含窗口边界、设置、复用、隔离、编辑删除、存储失败、分批恢复和工具边界；真实浏览器及模型链路须另行验收。
